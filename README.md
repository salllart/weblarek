# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера.  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

### Данные

Интернет-магазин работает с двумя типами данных объектов - **Товар** и **Покупатель**.

#### Товар

```
interface IProduct {
    id: string;
    description: string;
    image: string;
    title: string;
    category: string;
    price: number | null;
}
```

Интерфейс отвечает за структуру объекта, с которым будет работать корзина и каталог товаров для их отображения и обработки.

Данные о продукте:  
id - уникальный идентификатор продукта;  
description - описание продукта;
image - пукть к изображению продукта;
title - название продукта;
category - категория товара;
price - цена продукта, продукт может не иметь цены, тогда значение будет `null`;

#### Покупатель

```
interface IBuyer {
    payment: TPayment;
    email: string;
    phone: string;
    address: string;
}
```

Интерфейс отвечает за структуру объекта данных пользователя при оформлении заказа. Строки типа `TPayment` могут принимать значения `'card'`, `'cash'` или пустую строку.

Данные пользователя:  
payment - вид оплаты, онлайн или при получении;
email - емэйл покупателя;
phone - номер телефона покупателя;
address - адресс для доставки;

### Модель данных

#### Класс Catalog
Отвечает за хранение, получение и сохранение товаров в каталог интернет-магазина.

Конструктор класса не принимает параметров.

Поля класса:  
`products: IProduct[]` - хранит массив всех товаров.  
`currentProduct: IProduct | undefined` - хранит товар, выбранный для подробного отображения.

Методы:  
`setProducts(products: IProduct[]): void` - сохраняет массива товаров полученного в параметрах метода.  
`getProducts(): IProduct[]` - получает массив товаров из модели.  
`setCurrentProduct(product: IProduct): void` - сохраняет товар для подробного отображения.  
`getCurrentProduct(): IProduct | undefined` - получение товара для подробного отображения.  
`getProduct(id: string): IProduct` - получение одного товара по его id.  

#### Класс Cart
Отвечает за добавления и удаления товаров в корзину, а также за получение суммы стоимости товаров, их количества и узнает наличие товаров.

Конструктор класса не принимает параметров.

Поля класс:  
`products: IProduct[]` - хранит товары, которые пользователь выбрал для покупки.

Методы:  
`getProducts(): IProduct[]` - получение массива товаров, которые находятся в корзине.  
`addProduct(product: IProduct): void` - добавляет товар, который был получен в параметре, в массив корзины.  
`removeProduct(product: IProduct): void` - удаление товара, полученного в параметре из массива корзины.  
`clean(): void` - очистка корзины.  
`getTotal(): number` - получение стоимости всех товаров в корзине.  
`numberOfProducts(): number` - получение количества товаров в корзине.  
`isAvailable(id: string): boolean` - проверка наличия товара в корзине по его id, полученного в параметр метода.  

#### Класс Order
Модель отвечает за хранение и валидирования данных при оформлении заказа покупателем. Типы данных для работы класса:
```
type TValidation = {
    email?: string | undefined;
    payment?: string | undefined;
    phone?: string | undefined;
    address?: string | undefined;
}
```

Конструктор класса не принимает параметров.

Поля класса:  
`payment: TPayment` - хранит вид оплаты. Строки типа `TPayment` могут принимать значения `'card'`, `'cash'` или пустую строку.  
`email: string` - хранит email пользователя.  
`phone: string` - хранит номер телефона.  
`address: string` - хранит адрес.  

Методы:  
`setField(field: string, value: string | TPayment): void` - устанавливает значение по полю. Значение и поле получены из параметров метода.  
`getFields(): IBuyer` - получение всех данных покупателя.  
`clean(): void` - очистка данных покупателя.  
`isValid(): TValidation` - валидация данных. Если поля не проходят валидацию, то функция выдает объект, где ключ **название поле**, а значение **текст ошибки**. Если поле заполненно корректно, то его не будет в объекте валидации

### Слой коммуникации

#### Класс LarekApi

Является связующим классом между моделями данных и запросами с сервера.

Типы данных для работы класса:
```
interface IDataProducts {
    total: number;
    items: IProduct[];
}

interface IPostOrder extends IBuyer {
    total: number;
    items: string[];
}

interface ISuccessOrder {
    id: string;
    total: number;
}

interface IWrongOrder {
    error: string;
}
```

Конструктор:  
`constructor(api: IApi)` - В конструктор передается экземпляр класса Api, который принимает baseurl.

Поля класса:  
`api: IApi` - экземпляр класса Api.

Методы класса:  
`getData(): Promise<IDataProducts>` - выполняет запрос к серверу и возвращает объект с массивом товаров.  
`makeOrder(info: IPostOrder): Promise<ISuccessOrder | IWrongOrder>` - отправляет на сервер данные для заказа и возвращает его ответ.

### Слой представления

Слой представления отвечает только за отрисовку компонентов веб-проложения, а не за его логику. За логику отвечает презентер. Каждый класс слоя представления является потомком базового класса Component.

#### Класс Modal.

Класс отвечает за модальное окно, контент окна может быть любой компонент.

Конструктор:  
`constructor(container: HTMLElement)` - конструктор принимает HTML элемент модального окна.

Поля класса:  
`closeButtonElement: HTMLButtonElement` - кнопка закрытия модалки.  
`contentElement: HTMLElement` - контент модалки.  
`windowElement: HTMLElement` - окно модалки.

Методы класса:  
`open(): void` - открывает модальное окно и отобржает его.  
`render(data: IModalData): HTMLElement` - отрисовывет модальное окно и возвращает его.

Сеттеры класса:  
`content: HTMLElement` - задаёт контент для `contentElement`.

#### Класс Header.

Класс отвечает за шапку сайта. В шапке сайта есть кнопка корзины с счётчиком, которая открывает окно корзины.

Конструктор:  
`constructor(events: IEvents, container: HTMLElement)` - конструктор принимает HTML элемент шапки и брокер событий.

Поля класса:  
`buttonElement: HTMLButtonElement` - кнопка, которая открывает окно корзины.  
`counterElement: HTMLElement` - счётчик возле кнопки, отображает количество товаров в корзине.

Сеттеры класса:  
`counter(value: number)` - меняет текст counterElement. 

#### Класс Gallery.

Класс отвечает за отображение карточек товаров. Галлерея имет одну страницу без пагинации.

Конструктор:  
`constructor(container: HTMLElement)` - конструктор принимает HTML элемент галлереи.

Сеттеры класса:  
`items: HTMLElement[]` - принимает массив HTML элементов карточек товаров.

#### Класс Basket.

Класс отвечает за отображения корзины веб-приложения. Корзина является контентом для модального окна.

Конструктор:  
`constructor(events: IEvents, container: HTMLElement)` - конструктор принимает HTML элемент корзины и броккер событий.

Поля класса:  
`listElement: HTMLElement` - HTML элемент списка товаров корзины.  
`priceElement: HTMLElement` - HTML элемент стоимости всех товаров корзины.

Сеттеры класса:  
`list(value: HTMLElement[])` - добавляет карточки товаров в `listElement`.  
`price(value: number)` - устанавливает textContent в `priceElement`.

`priceElement: HTMLElement` - HTML элемент стоимости товара.

Сеттеры класса:  
`title(value: string)` - устанавливает textContent в `titleElement`.  
`price(value: number)` - устанавливает textContent в `priceElement`.

#### Класс CardCatalog.

Класс отвечает за отображение карточки товара в каталоге на главной странице. Наследуется от базового класса `Card`.

Конструктор:

```
interface ICardActions {
```

Поля класса:

`actions?: ICardActions` - объект колбэков компонента.

Сеттеры класса:  
`category(value: string)` - устанавливает textContent в `categoryElement` и применяет соответствующий CSS-класс модификатора категории.  
`image(value: string)` - устанавливает src для `imageElement`.

#### Класс CardPreview.

Класс отвечает за отображение подробной карточки товара в модальном окне. Наследуется от базового класса `Card`.

Конструктор:  
`constructor(container: HTMLElement, actions?: ICardPreviewActions)` - конструктор принимает HTML элемент карточки товара и объект с колбэком `onBuy`, который срабатывает при нажатии на кнопку покупки/удаления товара. Интерфейс ICardPreviewActions:

```
interface ICardPreviewActions {
```

Поля класса:  
`categoryElement: HTMLElement` - HTML элемент категории товара.  
`imageElement: HTMLImageElement` - HTML элемент изображения товара.  
`textElement: HTMLElement` - HTML элемент подробного описания товара.  
`buttonElement: HTMLButtonElement` - HTML элемент кнопки добавления/удаления товара в корзину.  
`actions?: ICardPreviewActions` - объект колбэков компонента.

Сеттеры класса:

`image(value: string)` - устанавливает src `imageElement`.  
`text(value: string)` - устанавливает textContent в `textElement`.
`disabled(value: boolean)` - устанавливает атрибут disabled в `buttonElement`.

### События веб-приложения.

При взаимодействии пользователия и изменении модели генерируются события, которые, с помощью брокера событий, обрабатываются презентером.

#### События формы.

События:  
`form-order:changed` - происходит когда пользователь выберает опцию или вводит в поле формы первого шага.  
`form-order:submitted` - происходит когда пользователь преходит ко вторму шагу формы.  
`form-contacts:changed` - происходит когда пользователь вводит в поле формы второго шага.  
`form-contacts:submitted` - просиходит когда пользователь заканчивает оформление заказа.  

#### События корзины.

События:  
`basket:open` - просиходит когда пользователь нажимает на кнопку открытия корзины в шапке.  
`basket:submitted` - происходит когда пользователь начинает оформление заказа.
